# Development Guidelines

## 1. 기본 원칙
- 기존 프로젝트의 구조와 코딩 스타일을 존중한다.
- 단순하고 명확한 구현을 우선하고 과도한 설계를 피한다.
- 요청하지 않은 기능이나 불필요한 의존성을 추가하지 않는다.

## 2. 작업 절차
- 수정 전에 관련 코드와 영향 범위를 분석한다.
- 복잡한 작업은 구현 전에 계획을 수립한다.
- 기존 기능을 유지하면서 최소한의 코드만 변경한다.

## 3. 코드 품질
- 의미 있는 이름을 사용하고 중복 코드를 최소화한다.
- 함수와 모듈은 하나의 책임을 갖도록 작성한다.
- 오류를 무시하지 않고 원인을 분석하여 해결한다.

## 4. 보안
- API 키, 비밀번호 등 민감정보를 코드에 포함하지 않는다.
- 외부 입력을 검증하고 안전하게 처리한다.
- 인증 및 권한 검사를 철저히 수행한다.

## 5. 테스트 및 검증
- 변경 후 관련 테스트와 빌드를 수행한다.
- 정상 사례뿐 아니라 예외 상황도 검토한다.
- 검증하지 않은 결과를 성공했다고 보고하지 않는다.

## 6. 작업 관리 및 보고
- 기존 사용자 변경 사항을 임의로 삭제하거나 되돌리지 않는다.
- Git commit, push는 요청받은 경우에만 수행한다.
- 작업 완료 후 변경 사항과 검증 결과를 한국어로 간결하게 보고한다.
