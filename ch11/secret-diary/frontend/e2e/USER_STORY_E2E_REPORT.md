## 발견된 결함 및 조치

이번 검증 중 유닛/컴포넌트 테스트로는 드러나지 않던 실제 통합 결함 2건을 발견해 즉시 수정했다(모두 재검증하여 PASS 처리).

### 1. US-A3 AC-3 — Refresh Token 만료/위조 시 로그인 화면으로 이동하지 않음
- **증상**: `httpClient`가 refresh 실패 시 세션(토큰)은 정리하지만, 현재 화면에 머물러 있을 때는 로그인 화면으로 자동 이동하지 않고 빈 화면에 머무름.
- **원인**: `auth:logout` 커스텀 이벤트를 구독해 세션을 지우는 로직(`stores/auth.js`)은 있었지만, 이 이벤트를 받아 **라우터 이동**을 트리거하는 코드가 어디에도 없었음(라우트 가드는 실제 네비게이션 시도가 있을 때만 재평가됨).
- **조치**: `src/router/index.js`에 `window.addEventListener('auth:logout', ...)`를 추가해, 현재 라우트가 `requiresAuth`인 경우 `router.push({ name: 'login' })`을 수행하도록 수정.
- **파일**: `frontend/src/router/index.js`

### 2. US-B5 AC-4 — 수정 화면에서 타인/미존재 일기 접근 시 아무 안내 없이 빈 폼 노출
- **증상**: 사용자 B가 사용자 A 소유 일기의 `/diaries/{id}/edit` URL로 직접 접근하면, 상세 화면과 달리 403/404 에러가 전혀 처리되지 않고 완전히 빈 작성 폼처럼 보임(사실상 새 일기 작성 화면과 구분 불가).
- **원인**: `DiaryFormPage.vue`가 `useDiaryQuery`의 `isLoading`만 처리하고 `isError`는 전혀 다루지 않았음.
- **조치**: `isError`를 구독해 수정 모드에서 조회 실패 시 `DiaryDetailPage.vue`와 동일한 "찾을 수 없거나 접근 권한이 없습니다." 안내를 표시하도록 수정.
- **파일**: `frontend/src/pages/DiaryFormPage.vue`

두 수정 모두 기존 Vitest 63개 테스트와 Playwright E2E 5개 테스트가 그대로 통과함을 재확인했다.
