# 업무일지 앱 PRD

## 1. 개요

### 1.1 배경
직장인은 매일 자신의 업무 내용, 성과, 문제점, 계획을 기록할 필요가 있다. 종이나 사내 메신저, 개인 문서로 흩어져 관리되는 업무일지는 검색과 이력 관리가 어렵고, 과거 기록을 다시 찾아보기 힘들다. 이를 해결하기 위해 개인이 자신의 업무일지를 온라인으로 작성·조회·관리할 수 있는 웹 애플리케이션이 필요하다.

### 1.2 목표
- 사용자가 매일의 업무 내용을 간단한 양식으로 손쉽게 작성할 수 있도록 한다.
- 작성된 업무일지를 완료여부 기준으로 조회할 수 있도록 한다.
- 회원가입/로그인 기반의 개인화된 업무일지 관리 환경을 제공한다.

### 1.3 비목표
- 팀/조직 단위의 업무일지 공유, 결재, 승인 워크플로우는 다루지 않는다.
- 업무 시간 집계, 근태 관리, 프로젝트 일정 관리(간트차트 등) 기능은 포함하지 않는다.
- 알림, 이메일 발송, 캘린더 연동 등 외부 서비스 연동은 이번 범위에서 제외한다.

## 2. 문제 정의

### 2.1 사용자 문제
- 업무일지를 자유 형식(메모, 메신저 등)으로 작성하다 보니 항목 누락이 잦고 일관성이 없다.
- 입력 항목이 너무 많으면 매일 작성하는 부담이 커져 기록을 미루게 된다.
- 자신이 그동안 얼마나 많은 업무일지를 작성했는지 파악하기 어렵다.

## 3. 목표 및 성공 지표

### 3.1 핵심목표
- 회원가입/로그인한 사용자가 간단한 양식으로 업무일지를 작성할 수 있다.
- 작성된 업무일지를 완료여부로 필터링하여 조회할 수 있다.
- 사용자 본인 정보(패스워드 변경, 작성한 업무일지 갯수)를 조회/관리할 수 있다.

### 3.2 성공 지표
- 사용자가 하루 1회 이상 업무일지를 작성할 수 있는 흐름이 오류 없이 동작한다.
- 필터링 조회 시 결과가 조건에 맞게 정확히 반환된다.
- 회원가입부터 업무일지 작성, 조회, 계정 정보 관리까지 전 과정이 끊김 없이 동작한다.

### 3.3 실패 조건
- 로그인하지 않은 사용자가 업무일지 작성/조회 기능에 접근 가능한 경우
- 업무일지 필수 항목 누락 시에도 저장이 되는 경우
- 다른 사용자의 업무일지가 조회/수정되는 경우 (데이터 격리 실패)

## 4. 사용자 시나리오

### 4.1 페르소나
- **김대리**: 매일 업무 종료 전 업무일지를 작성해야 하는 직장인. 항목이 많은 양식에 지쳐 있으며, 최소한의 입력으로 빠르게 기록하고 싶어한다.

### 4.2 사용자 스토리
- 사용자로서, 나는 회원가입 후 로그인하여 나만의 업무일지 공간에 접근하고 싶다.
- 사용자로서, 나는 오늘의 업무일지를 간단한 양식(작성일자, 제목, 업무내용, 문제점 및 해결방안, 완료여부, 내일 계획)에 맞춰 작성하고 싶다.
- 사용자로서, 나는 완료여부로 내 업무일지를 필터링해서 찾고 싶다.
- 사용자로서, 나는 내 계정의 패스워드를 변경하고, 지금까지 작성한 업무일지 갯수를 확인하고 싶다.

## 5. 요구사항

### 5.1 기능 요구사항
- **인증/계정**
  - 회원가입 및 로그인 기능 (로그인은 email/password만 사용. 전용 고유 식별자는 가입 시 서버가 자동 부여)
  - JWT 기반 인증 (Access Token 12시간, Refresh Token 7일 유효)
  - 로그인한 사용자만 업무일지 기능 이용 가능
  - 패스워드 변경 기능
  - 내가 작성한 업무일지 갯수 조회
- **업무일지 작성** (입력 순서: 작성일자, 제목, 업무내용, 문제점 및 해결방안, 완료여부, 내일 계획)
  - 작성일자 (요일은 작성일자를 기준으로 시스템이 자동 계산하여 표시, 별도 입력 불필요)
  - 제목, 업무 내용, 완료여부 (필수)
  - 문제점 및 해결방안 (선택)
  - 내일 계획 (선택)
- **업무일지 조회**
  - 본인이 작성한 업무일지 목록 조회
  - 완료여부로 필터링 조회
- **업무일지 수정/삭제**
  - 본인이 작성한 업무일지 수정
  - 본인이 작성한 업무일지 삭제 (실제 행을 삭제하지 않고 삭제 플래그만 지정하는 소프트 삭제, 삭제된 업무일지는 목록/상세 조회에서 제외)

### 5.2 비기능 요구사항
- 3-tier 아키텍처: 프론트엔드(React 19) / 백엔드(Node + Express, JavaScript) / 데이터베이스(Supabase PostgreSQL)
- 백엔드는 SOLID 원칙과 Clean 아키텍처를 준수
- 프론트엔드는 Tanstack Query로 백엔드 통신, 전역 상태 관리 라이브러리 사용
- 인증은 자체 JWT 구현 (Access/Refresh Token)
- 사용자별 데이터 접근 격리 (본인 업무일지만 조회/수정 가능)

### 5.3 우선 순위 기준
1. 회원가입/로그인/인증 (필수 선행 기능)
2. 업무일지 작성 (핵심 기능)
3. 업무일지 조회/필터링
4. 업무일지 수정/삭제
5. 사용자 정보 조회/패스워드 변경/작성 갯수 조회

## 6. 사용자 흐름
1. 사용자가 회원가입 페이지에서 이름, 부서, email, 패스워드를 입력해 가입한다 (고유 식별자는 서버가 자동 부여).
2. 로그인하여 Access/Refresh Token을 발급받는다.
3. 업무일지 작성 화면에서 작성일자/제목/업무내용/문제점 및 해결방안/완료여부/내일 계획을 채워 저장한다.
4. 업무일지 목록 화면에서 완료여부 필터를 적용해 원하는 업무일지를 조회한다.
5. 마이페이지에서 패스워드를 변경하거나 작성한 업무일지 갯수를 확인한다.

## 7. 범위

### 7.1 In Scope
- 회원가입/로그인/JWT 인증
- 업무일지 작성 (작성일자, 제목, 업무내용, 문제점 및 해결방안, 완료여부, 내일 계획)
- 업무일지 목록/필터 조회 (완료여부)
- 업무일지 수정, 삭제 (소프트 삭제)
- 사용자 정보 조회, 패스워드 변경, 작성 갯수 조회

### 7.2 Out of Scope
- 팀/조직 공유, 결재, 승인 워크플로우
- 업무 시간 집계, 근태, 일정 관리
- 알림, 이메일, 캘린더 등 외부 연동
- 소셜 로그인 등 제3자 인증 연동

## 8. 엣지 케이스, 예외 처리할 것
- 필수 항목(제목, 업무 내용, 완료여부 등) 누락 시 저장 시도
- 동일 날짜에 중복으로 업무일지를 작성하려는 경우
- 만료된 Access Token으로 요청하는 경우 (Refresh Token으로 재발급 처리)
- Refresh Token까지 만료된 경우 재로그인 유도
- 다른 사용자의 업무일지 ID로 직접 접근을 시도하는 경우 (권한 오류 처리)
- 삭제(삭제 플래그 지정)된 업무일지를 목록/상세 조회하는 경우 (조회 결과에서 제외)
- 이미 삭제된 업무일지를 다시 수정/삭제하려는 경우
- 패스워드 변경 시 기존 패스워드 검증 실패

## 9. 작업 일정
전체 개발 기간은 2일 이내로 진행한다.

| 일차 | 내용 |
|---|---|
| 1일차 | DB 스키마 설계, 인증(회원가입/로그인/JWT) 및 업무일지 작성/조회 API 구현 |
| 2일차 | 프론트엔드(인증, 업무일지 작성/필터 조회, 마이페이지) 구현 및 통합 테스트 |
