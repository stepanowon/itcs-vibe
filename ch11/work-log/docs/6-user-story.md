# 업무일지 앱 사용자 시나리오

`docs/1-prd.md`, `docs/2-erd.md`, `docs/4-swagger.json`, `docs/5-wireframe.md` 기준으로 작성.

## 페르소나
- **김대리**: 매일 업무 종료 전 업무일지를 작성해야 하는 직장인. 항목이 많은 양식에 지쳐 있고, 최소한의 입력으로 빠르게 기록하고 싶어한다.

## 1. 회원가입

**사용자 스토리**: 사용자로서, 나는 이름/부서/이메일/패스워드만으로 간단히 회원가입하여 나만의 업무일지 공간을 만들고 싶다.

| 시나리오 | Given | When | Then |
|---|---|---|---|
| 회원가입 성공 | 아직 가입하지 않은 사용자가 회원가입 화면에 있다 | 이름/부서/이메일/패스워드를 모두 입력하고 가입 버튼을 누른다 | 계정이 생성되고(고유 식별자는 서버가 자동 부여) 로그인 화면으로 이동한다 |
| 중복 이메일 | 이미 사용중인 이메일이 있다 | 동일한 이메일로 가입을 시도한다 | 409 오류와 함께 "이미 사용 중인 이메일" 안내를 본다 |
| 필수 항목 누락 | 회원가입 화면에 있다 | 일부 필드를 비운 채 가입 버튼을 누른다 | 400 오류와 함께 어떤 항목이 비었는지 안내를 본다 |

## 2. 로그인 / 토큰 관리

**사용자 스토리**: 사용자로서, 나는 이메일과 패스워드로 로그인하여 Access/Refresh Token을 발급받고 싶다.

| 시나리오 | Given | When | Then |
|---|---|---|---|
| 로그인 성공 | 가입된 계정이 있다 | 올바른 이메일/패스워드로 로그인한다 | Access Token(12시간)과 Refresh Token(7일)을 발급받고 업무일지 목록으로 이동한다 |
| 로그인 실패 | 가입된 계정이 있다 | 잘못된 패스워드로 로그인한다 | 401 오류와 함께 "이메일 또는 패스워드 불일치" 안내를 본다 |
| Access Token 만료 후 재발급 | 로그인 상태에서 12시간이 지나 Access Token이 만료됐다 | 유효한 Refresh Token으로 재발급을 요청한다 | 새 Access Token을 발급받아 로그인 상태가 유지된다 |
| Refresh Token까지 만료 | Refresh Token 발급 후 7일이 지났다 | API를 다시 호출한다 | 401 오류를 받고 재로그인 화면으로 이동한다 |
| 로그아웃 | 로그인 상태다 | 마이페이지에서 로그아웃을 누른다 | Refresh Token이 무효화(revoke)되고 로그인 화면으로 이동한다 |

## 3. 업무일지 작성

**사용자 스토리**: 사용자로서, 나는 오늘의 업무일지를 간단한 양식(작성일자/제목/업무내용/문제점 및 해결방안/완료여부/내일계획)에 맞춰 작성하고 싶다.

| 시나리오 | Given | When | Then |
|---|---|---|---|
| 작성 성공 | 로그인 상태이고 오늘 날짜로 아직 업무일지를 쓰지 않았다 | 작성 화면에서 필수 항목(제목/업무내용/완료여부)을 채우고 저장한다 | 업무일지가 저장되고 상세 화면으로 이동한다 |
| 선택 항목 미입력 | 로그인 상태이고 작성 화면에 있다 | 문제점 및 해결방안, 내일 계획을 비운 채 필수 항목만 채워 저장한다 | 업무일지가 정상적으로 저장된다 |
| 필수 항목 누락 | 작성 화면에 있다 | 제목이나 업무내용을 비운 채 저장한다 | 400 오류와 함께 안내를 본다 |
| 동일 날짜 중복 작성 | 오늘 날짜로 이미 작성한(삭제되지 않은) 업무일지가 있다 | 같은 날짜로 다시 작성을 시도한다 | 409 오류와 함께 "이미 작성된 업무일지가 있음" 안내를 본다 |
| 삭제된 날짜 재작성 | 오늘 날짜의 업무일지를 삭제(소프트 삭제)한 적이 있다 | 같은 날짜로 다시 작성한다 | 새 업무일지가 정상적으로 저장된다 |

## 4. 업무일지 목록/필터 조회

**사용자 스토리**: 사용자로서, 나는 완료여부로 내 업무일지를 필터링해서 찾고 싶다.

| 시나리오 | Given | When | Then |
|---|---|---|---|
| 전체 목록 조회 | 여러 건의 업무일지를 작성했다 | 목록 화면에 진입한다 | 본인이 작성한 삭제되지 않은 업무일지만 최신순으로 보인다 |
| 완료여부로 필터링 | 완료/진행중 업무일지가 섞여 있다 | 완료여부 필터를 선택한다 | 조건에 맞는 업무일지만 보인다 |
| 다른 사용자 데이터 미노출 | 다른 사용자도 업무일지를 작성했다 | 내 목록을 조회한다 | 다른 사용자의 업무일지는 보이지 않는다 |

## 5. 업무일지 상세 조회 / 수정 / 삭제

**사용자 스토리**: 사용자로서, 나는 내가 작성한 업무일지를 다시 확인하고, 필요하면 수정하거나 삭제하고 싶다.

| 시나리오 | Given | When | Then |
|---|---|---|---|
| 상세 조회 성공 | 목록에 내 업무일지가 있다 | 항목을 선택한다 | 작성한 모든 항목이 표시된 상세 화면을 본다 |
| 다른 사용자 업무일지 접근 | 다른 사용자의 업무일지 ID를 알고 있다 | 해당 ID로 상세 조회를 시도한다 | 403 오류로 접근이 거부된다 |
| 수정 성공 | 내가 작성한 업무일지 상세 화면에 있다 | 일부 항목을 수정하고 저장한다 | 변경된 내용이 반영되고 상세 화면에 최신 내용이 보인다 |
| 삭제(소프트 삭제) | 내가 작성한 업무일지 상세 화면에 있다 | 삭제를 누르고 확인한다 | 업무일지의 삭제 플래그가 지정되고, 이후 목록/상세 조회에 더 이상 보이지 않는다 |
| 삭제된 업무일지 재접근 | 이미 삭제한 업무일지 ID가 있다 | 해당 ID로 상세/수정/삭제를 시도한다 | 404 오류로 "존재하지 않는 업무일지"로 처리된다 |

## 6. 마이페이지 (내 정보 / 패스워드 변경 / 작성 갯수)

**사용자 스토리**: 사용자로서, 나는 내 계정 정보를 확인하고 패스워드를 변경하며, 지금까지 작성한 업무일지 갯수를 확인하고 싶다.

| 시나리오 | Given | When | Then |
|---|---|---|---|
| 내 정보 조회 | 로그인 상태다 | 마이페이지에 진입한다 | 이름/부서/이메일과 작성한 업무일지 갯수(삭제 제외)를 본다 |
| 패스워드 변경 성공 | 마이페이지에 있다 | 올바른 기존 패스워드와 새 패스워드를 입력해 변경한다 | 패스워드가 변경되고 변경 완료 안내를 본다 |
| 패스워드 변경 실패 | 마이페이지에 있다 | 기존 패스워드를 틀리게 입력한다 | 400 오류와 함께 "기존 패스워드 불일치" 안내를 본다 |
| 로그인하지 않은 접근 | 로그인하지 않았다 | 업무일지/마이페이지 기능에 접근을 시도한다 | 401 오류로 로그인 화면으로 이동한다 |
