## 개요

본 문서는 `1-prd.md`의 5.1 기능 요구사항과 `2-user-scenario.md`의 각 시나리오를 기반으로 화면 레이아웃을 텍스트(ASCII) 와이어프레임으로 정의한다. 실제 시각 디자인(색상, 폰트, 컴포넌트 스타일)은 별도 디자인 시스템 문서에서 다루며, 본 문서는 화면 구조·정보 배치·상태 표현에 집중한다.

와이어프레임 표기 규칙:

- `[ 버튼 ]` : 버튼
- `[ 버튼(비활성) ]` : disabled 버튼
- `( ) 라디오` , `[ ] 체크박스`
- `[________]` : 텍스트 입력 필드
- `[ v ]` : 드롭다운/셀렉트
- `⚠` : 에러/경고 메시지 영역

### 반응형 원칙

동시 접속자 20명 이하 소규모 사업장 대상이며 데스크톱/모바일 브라우저를 함께 사용한다(PRD 5.2). 별도 모바일 네이티브 앱은 없으므로(1.3 비목표) 반응형 웹으로 모바일 사용성을 확보한다.

| 브레이크포인트      | 대상           | 레이아웃 방침                                                                             |
| ------------------- | -------------- | ----------------------------------------------------------------------------------------- |
| ~767px (모바일)     | 스마트폰       | 1단 세로 스택, 네비게이션은 햄버거 메뉴로 축소, 테이블은 카드 리스트로 전환               |
| 768~1023px (태블릿) | 태블릿/작은 창 | 1~2단 혼합, 테이블은 가로 스크롤 유지, 네비게이션은 텍스트 메뉴 유지(공간 부족 시 햄버거) |
| 1024px~ (데스크톱)  | PC             | 앞서 정의한 기본 와이어프레임 그대로 사용                                                 |

공통 규칙:

- 폭이 좁은 화면에서 여러 컬럼 테이블(5, 6, 7, 8번 화면)은 행마다 "라벨: 값" 형태의 카드로 재배치한다.
- 버튼/입력 필드는 모바일에서 폭 100%로 늘어나며 터치 타겟 확보를 위해 세로 여백을 늘린다.
- 모달(5, 8번 화면)은 Bootstrap 기본 모달(`modal-dialog-centered`)을 그대로 사용하며, 별도의 풀스크린 전환 없이 모바일에서도 중앙 정렬된 카드 형태로 표시된다.

## 1. 회원가입 화면

### 화면 목적

신규 사용자가 email/이름/사번/입사일/비밀번호를 입력해 계정을 생성한다. 최초 가입자는 자동으로 manager, 이후는 employee로 등록된다(PRD 5.1, 시나리오 1).

│                 회원가입                       │
│  ┌──────────────────────────────────────────┐│
│  │ 이메일                                     ││
│  │ [________________________________]        ││
│  │                                            ││
│  │ 이름                                       ││
│  │ [________________________________]        ││
│  │                                            ││
│  │ 사번                                       ││
│  │ [________________________________]        ││
│  │ ⚠ 이미 등록된 사번입니다                    ││
│  │                                            ││
│  │ 입사일                                     ││
│  │ [ 2026-08-19            ▾ ]  (date picker) ││
│  │                                            ││
│  │ 비밀번호                                   ││
│  │ [________________________________]        ││
│  │                                            ││
│  │ 비밀번호 확인                              ││

### 주요 UI 요소

- 이메일/이름/사번/입사일/비밀번호/비밀번호 확인 입력 필드
- "가입하기" 버튼: 모든 필드 입력 및 클라이언트 유효성 통과 시에만 활성화
- 하단 "로그인" 링크로 로그인 화면 이동
- 폼 하단에 "※ 최초 가입자는 자동으로 manager 권한이 부여됩니다" 안내 배너 표시(실제 배정은 가입 후 시스템이 자동 판단, 시나리오 1)

### 상태/예외

- 사번 중복(409): 사번 입력 필드 하단에 `⚠ 이미 등록된 사번입니다` 표시, 가입 미진행, 화면 유지(시나리오 1 예외 상황)
- 비밀번호/비밀번호 확인 불일치: 제출 전 클라이언트에서 즉시 경고, "가입하기" 버튼 비활성화
- 필수 필드 미입력: 버튼 비활성화 또는 제출 시 필드별 경고 표시
- 가입 성공 시: 완료 토스트/메시지 노출 후 로그인 화면으로 자동 이동(시나리오 1)

## 2. 로그인 화면

### 화면 목적

가입된 사용자가 이메일/비밀번호로 로그인하고 Access/Refresh Token을 발급받는다(PRD 5.1).

### 와이어프레임

```
┌──────────────────────────────────────────────┐
│                근태관리 앱                     │
│                                                │
│                  로그인                        │

│  │ 이메일                                     ││
│  │ [________________________________]        ││
│  │                                            ││
│  │ 비밀번호                                   ││
│  │ [________________________________]        ││
│  │                                            ││
│  │ ⚠ 이메일 또는 비밀번호가 올바르지 않습니다   ││
│  │                                            ││
│  │           [        로그인          ]       ││
│  └──────────────────────────────────────────┘│
│                                                │
│         계정이 없으신가요? 회원가입             │
└──────────────────────────────────────────────┘
```

### 주요 UI 요소

- 이메일/비밀번호 입력 필드
- "로그인" 버튼
- 하단 "회원가입" 링크

### 상태/예외

- 인증 실패(401): 이메일/비밀번호 불일치 시 공통 에러 메시지 표시(계정 존재 여부 노출 방지)
- 로그인 미상태에서 근태 관련 화면(대시보드 등) 직접 접근 시 이 화면으로 리다이렉트(시나리오 1 기대 결과)
- 비활성(inactive) 계정 로그인 시도 시 403 및 "비활성화된 계정입니다" 등 안내(PRD 8. 엣지 케이스)
- 로그인 성공 시 대시보드로 이동, Access Token(12시간)/Refresh Token(7일) 저장

- "출근 체크인" / "퇴근 체크아웃" 버튼
- 이번 달 요약 카드(출근일수, 잔여 연차일수) - 대시보드 진입 시 참고용 정보

### 상태/예외

- 모바일(~767px)에서는 두 버튼이 가로 배치 대신 세로로 쌓이고 폭 100%로 늘어나 터치 조작을 쉽게 한다(위 모바일 와이어프레임 참고).
- 초기 상태: 체크인 전 → 체크아웃 버튼 비활성화(체크인 기록 없이 체크아웃 불가, 시나리오 2 예외 B)
- 체크인 클릭 시: 서버 확인 후 성공하면 버튼이 "체크인 완료(HH:MM)"로 즉시 비활성화, 퇴근 버튼 활성화
- 이미 체크인한 상태에서 버튼 재클릭 불가(비활성화). API 직접 재호출 시 409 "이미 체크인하셨습니다" 에러를 토스트로 표시(시나리오 2 예외 A)
- 체크아웃 클릭 시: 서버 확인 후 성공하면 화면에 체크아웃 시각이 갱신 표시된다. 체크인 버튼과 달리 "퇴근 체크아웃" 버튼은 비활성화되지 않고, 이후에도 여러 번 클릭할 수 있으며 클릭할 때마다 체크아웃 시각이 최종 클릭 시각으로 덮어써진다(같은 근무일 레코드 갱신, 새 레코드 생성 아님)
- 체크인 없이 체크아웃 시도(API 직접 호출 등) 시 400 "체크인 기록이 없습니다" 에러 표시
- 자정 이후 접속 시에도 work_date는 체크인 시각 기준으로 결정되므로, 전날 밤 체크인한 근무가 익일 화면에서 "체크아웃 대기 중(전일 근무)"으로 계속 노출될 수 있음(시나리오 2 예외 C)

- "※ 잔여 연차일수 내에서만 신청할 수 있습니다" 안내 배너(신청 버튼 위, 상시 노출)
- "신청" 버튼

- 신청 일수 > 잔여 연차일수: 제출 시 400 응답, `⚠ 잔여 연차일수가 부족합니다` 표시, 신청 미생성(시나리오 3 예외 B)
- 정상 제출 시: 신청 내역 목록에 "대기중" 상태로 즉시 반영(시나리오 3 기대 결과)

- 신청 일수는 종일(1일) 또는 반차(0.5일) 단위로만 계산된다.

- 처리 완료 후 해당 건은 "대기중" 필터 목록에서 사라짐
- 이미 처리된 건 재처리 시도(예: 새로고침 지연 화면에서 중복 클릭) 시 409 "이미 처리된 신청입니다" 에러 토스트, 상태는 기존 결과 유지(시나리오 4 예외 상황 A)
- 승인 시 신청자의 잔여 연차일수에서 해당 일수 즉시 차감(시나리오 4 기대 결과)

## 10. 공통 네비게이션 (역할별 메뉴 차이)

### 화면 목적

로그인 후 모든 화면에 공통으로 표시되는 네비게이션. 상단바(로고/사용자/로그아웃) + 좌측 사이드바(메뉴)로 구성하며, 역할(employee/manager)에 따라 사이드바 메뉴가 다르다(PRD 5.1 RBAC). `docs/style-guide.md` 참고(유사 앱 스크린샷 기반으로 좌측 사이드바 채택).

### 와이어프레임 - employee 로그인 시(데스크톱/태블릿, 768px~)

```
┌──────────────────────────────────────────────────────────┐
│ 근태관리 앱                          김사원님(직원) [로그아웃]│
├───────────┬──────────────────────────────────────────────┤
│ 대시보드   │                                              │
│ 연차 신청  │                                              │
│ 내 근태현황 │              (화면별 본문 영역)                │
│ 내 정보    │                                              │
│           │                                              │
└───────────┴──────────────────────────────────────────────┘
```

### 와이어프레임 - manager 로그인 시(데스크톱/태블릿, 768px~)

```
┌──────────────────────────────────────────────────────────┐
│ 근태관리 앱                          박팀장님(관리자) [로그아웃]│
├───────────┬──────────────────────────────────────────────┤
│ 대시보드   │                                              │
│ 연차 신청  │                                              │
│ 연차 승인관리│              (화면별 본문 영역)                │
│ 전체근태현황│                                              │
│ 사용자 관리 │                                              │
│ 내 정보    │                                              │
└───────────┴──────────────────────────────────────────────┘
```

"(직원)"/"(관리자)"는 역할 배지(pill)로 표시한다(`style-guide.md` 4절).

### 와이어프레임 - 모바일(~767px), employee 예시

```
┌───────────────────────┐
│ 근태관리 앱   [ ☰ ]     │  ← 햄버거 메뉴 버튼
└───────────────────────┘

[ ☰ ] 클릭 시 전체화면 드로어:
┌───────────────────────┐
│ 김사원님          [ X ]│
│───────────────────────│
│ 대시보드                │
│ 연차 신청               │
│ 내 근태 현황            │
│ 내 정보                │
│───────────────────────│
│ [      로그아웃      ] │
└───────────────────────┘
```

### 주요 UI 요소 및 역할별 메뉴 매핑

| 메뉴           | employee | manager | 비고                                              |
| -------------- | -------- | ------- | ------------------------------------------------- |
| 대시보드       | O        | O       | 체크인/체크아웃(3번 화면)                         |
| 연차 신청      | O        | O       | employee/manager 공통, 본인 명의로 신청(4번 화면) |
| 연차 승인 관리 | -        | O       | manager 전용(5번 화면)                            |
| 내 근태 현황   | O        | -       | 본인 월별 조회(6번 화면)                          |
| 전체 근태 현황 | -        | O       | manager 전용(7번 화면)                            |
| 사용자 관리    | -        | O       | manager 전용, 관리자 계정 생성 포함(8번 화면)     |
| 내 정보        | O        | O       | 공통(9번 화면)                                    |
| 로그아웃       | O        | O       | 클라이언트 토큰 즉시 삭제(시나리오 9)             |

### 상태/예외

- 768px 미만에서는 좌측 사이드바 대신 상단바의 햄버거 메뉴(`☰`)로 전환되고, 클릭 시 화면 전체를 덮는 드로어 메뉴가 열린다. 태블릿(768~1023px) 이상에서는 좌측 사이드바를 그대로 유지한다.
- employee 계정에는 "연차 승인 관리", "전체 근태 현황", "사용자 관리" 메뉴 자체가 표시되지 않음(프론트 RBAC)
- 메뉴 미노출과 별개로, 해당 화면 URL에 직접 접근하거나 API를 직접 호출하는 경우 백엔드 RBAC이 403으로 차단(PRD 5.1, 5.2, 시나리오 6/7)
- 로그인하지 않은 상태에서는 네비게이션 대신 로그인/회원가입 링크만 노출되며, 보호된 경로 접근 시 로그인 화면으로 리다이렉트(시나리오 1)
- "로그아웃" 클릭 시 즉시 Access/Refresh Token 삭제 후 로그인 화면 이동. 이후 뒤로가기로 재접근 시에도 토큰 부재로 로그인 화면 유지(시나리오 9)
- Access Token 만료 후 Refresh Token으로 자동 재발급 시도, Refresh Token도 만료된 경우 401 응답 수신 시 로그인 화면으로 강제 이동(PRD 8. 엣지 케이스)
